# File Transfer: Uploads and Downloads

[Docs Home](../README.md) | [English Index](./README.md) | [中文](../zh/file-transfer.md)

Plain JSON endpoints only need input and output structs. File uploads use `multipart/form-data`, `form:"..."`, and `file:"..."`; file downloads return `*ninja.Download`.

If you want the binding rules for JSON bodies, URL encoded forms, and multipart forms first, read [Request Body and Form Data](./request-body-and-forms.md). This page focuses on uploads, downloads, and file streaming.

## Single-File Upload

For uploads, normal form fields still use `form:"..."`, while file fields use `file:"..."`:

```go
type UploadAvatarInput struct {
    UserID uint                `path:"id" binding:"required"`
    Title  string              `form:"title"`
    File   *ninja.UploadedFile `file:"file" binding:"required"`
}

type UploadAvatarOutput struct {
    Filename string `json:"filename"`
    Size     int64  `json:"size"`
}

func uploadAvatar(ctx *ninja.Context, in *UploadAvatarInput) (*UploadAvatarOutput, error) {
    data, err := in.File.Bytes()
    if err != nil {
        return nil, err
    }

    // Save data to object storage or the local filesystem.
    _ = data

    return &UploadAvatarOutput{
        Filename: in.File.Filename,
        Size:     in.File.Size,
    }, nil
}

ninja.Post(router, "/:id/avatar", uploadAvatar,
    ninja.Summary("Upload avatar"),
)
```

Request example:

```bash
curl -X POST http://localhost:8080/users/1/avatar \
  -F "title=Avatar" \
  -F "file=@avatar.png"
```

## Multi-File Upload

Repeated multipart file fields can bind to `[]*ninja.UploadedFile`:

```go
type UploadImagesInput struct {
    Album string                `form:"album" binding:"required"`
    Files []*ninja.UploadedFile `file:"files" binding:"required"`
}

type UploadImagesOutput struct {
    Album     string   `json:"album"`
    FileCount int      `json:"file_count"`
    Names     []string `json:"names"`
}

func uploadImages(ctx *ninja.Context, in *UploadImagesInput) (*UploadImagesOutput, error) {
    names := make([]string, 0, len(in.Files))
    for _, file := range in.Files {
        names = append(names, file.Filename)
    }
    return &UploadImagesOutput{
        Album:     in.Album,
        FileCount: len(in.Files),
        Names:     names,
    }, nil
}
```

Request example:

```bash
curl -X POST http://localhost:8080/albums/summer/images \
  -F "album=summer" \
  -F "files=@a.jpg" \
  -F "files=@b.jpg"
```

## UploadedFile

`ninja.UploadedFile` wraps `multipart.FileHeader`:

| Member | Use |
| --- | --- |
| `Filename` | Original filename |
| `Size` | File size |
| `Open()` | Opens a file stream, good for large files |
| `Bytes()` | Reads the whole file into memory, good for small files |

Read a small file:

```go
data, err := in.File.Bytes()
if err != nil {
    return nil, err
}
```

Stream a large file:

```go
reader, err := in.File.Open()
if err != nil {
    return nil, err
}
defer reader.Close()

// Copy reader to object storage or local storage.
```

`Bytes()` reads the entire file into memory. In production, prefer `Open()` for larger files and pair uploads with [upload limit middleware](./middleware-security.md#upload-limits) so oversized requests do not reach business logic.

## File Downloads

Download small files or dynamically generated bytes:

```go
func downloadReport(ctx *ninja.Context, _ *struct{}) (*ninja.Download, error) {
    return ninja.NewDownload(
        "report.txt",
        "text/plain; charset=utf-8",
        []byte("hello from gin-ninja\n"),
    ), nil
}

ninja.Get(router, "/report", downloadReport,
    ninja.Summary("Download report"),
)
```

Download a stream:

```go
func streamReport(ctx *ninja.Context, _ *struct{}) (*ninja.Download, error) {
    body := strings.NewReader("streamed content\n")
    return ninja.NewDownloadReader(
        "report.txt",
        "text/plain; charset=utf-8",
        int64(body.Len()),
        body,
    ), nil
}
```

Common settings:

```go
download := ninja.NewDownload("report.pdf", "application/pdf", data)
download.Inline = true
download.Headers = map[string]string{"X-Report-Version": "v1"}
return download, nil
```

`Inline = true` changes `Content-Disposition` from attachment download to browser inline preview.

When a handler returns `*ninja.Download`, OpenAPI documents the success response as `application/octet-stream` with a `type: string`, `format: binary` schema. The actual response `Content-Type` still comes from the `contentType` passed to `NewDownload` / `NewDownloadReader` or from framework detection.

## Test Uploads

Use `ninjatest.Multipart` to build multipart requests:

```go
resp := client.Post("/uploads/single",
    ninjatest.Multipart(
        url.Values{"title": {"Avatar"}},
        ninjatest.File("file", "avatar.png", "image bytes"),
    ),
)
```

Multiple files:

```go
resp := client.Post("/uploads/many",
    ninjatest.Multipart(
        url.Values{"album": {"summer"}},
        ninjatest.File("files", "a.jpg", "A"),
        ninjatest.File("files", "b.jpg", "B"),
    ),
)
```

## Choosing A Shape

| Need | Recommended shape |
| --- | --- |
| Upload one small file | `*ninja.UploadedFile` + `Bytes()` |
| Upload a large file | `*ninja.UploadedFile` + stream with `Open()` |
| Upload several files | `[]*ninja.UploadedFile` |
| Upload files with regular fields | `file:"..."` + `form:"..."` |
| Return a small file | `ninja.NewDownload(...)` |
| Return streamed content | `ninja.NewDownloadReader(...)` |
| Browser inline preview | `download.Inline = true` |
